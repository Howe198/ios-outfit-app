# 搭配 App 第二批改版任务书（2026-11-26）

背景：第一批 7 条已全部合并（main 当前 3870218，含 PR #11 位置文案修正），新版已真机安装。本批 8 条来自 wan 真机体验后的反馈（2026-11-26 深夜，主聊天确认），由 Muse 对照计划审核，构建 agent 负责实现。

## 全局约束（每条都必须遵守，与第一批一致）

1. 全程 0 成本：不用任何付费 API、付费订阅、云端识别/云端生图服务。
2. 本地优先：照片处理、识别、统计全部在本机完成；照片、位置、穿搭数据不上传到任何服务器（天气查询沿用现有 Open-Meteo 口径，不在此列）。
3. 不抓取任何平台内容：淘宝、抖音、小红书、时尚杂志站等一律不自动抓取；灵感图片只能用本地 AI 生成图或 wan 手动收藏。
4. 已有用户数据（衣物、穿搭记录）必须完整保留，数据结构变更要有安全迁移。
5. 每项改动都要有失败回落（处理失败时保留原图/原流程可用，不能卡死添加流程）。
6. 每个 PR 的说明必须写清：对应条目、实现方式、成本（应为 0）、失败回落、自测结果；不自行合并，等 Muse 审核、wan 确认。

## 条目 1：灵感库扩充数量

现状：内置灵感只有 6 条，翻两下到底。
要求：
- 扩充到**不少于 30 条**，覆盖四季（春/夏/秋/冬）× 主要场合（日常休闲、通勤上班、正式场合），分布尽量均匀，不要都挤在一个季节。
- 每条含：平铺图、标题、场合、适用温度区间、简短说明（沿用现有数据结构与文案风格）。
- 图片来源：本地 AI 生成平铺图（与现有 6 条同一路数），简单日常搭配，不要夸张造型；单图体积要控制（压缩到合理大小，说明里给出新增图片总体积）。

## 条目 2：灵感按当地天气筛选排序

现状：灵感不分时宜混排（大夏天也可能先看到大衣）。
要求：
- 「搭配灵感」页和「今日」页的灵感区，按当天温度（复用现有定位取温能力；取温失败或用户改手动温度时用当前生效温度）与每条灵感的温度区间做匹配。
- 匹配的灵感排在前面，可加「适合今天」类标记；不匹配的排到后面或单独分区，不得混排在前面。
- 没有可用温度时回落：按当前季节的默认排序展示。
- 与条目 4(c) 的设置开关联动：开关关闭时恢复普通排序。

## 条目 3：灵感页两列网格左列被裁切（布局 bug，先修）

现状（wan 真机截图）：两列网格的**左列被屏幕左边缘切掉一截**——标题（如「白T + 直筒牛仔」的「白」字）、场合温度行、说明文字的左端都缺失，看起来歪歪扭扭、不居中；右列显示正常。
要求：
- 修复网格的边距/列宽计算：左右边距对称、两列等宽、卡片内文字完整显示不裁切。
- 在至少两种屏幕宽度（如 iPhone 16 Pro Max 与较小屏机型模拟器）上自测截图确认。
- 这是纯布局修复，不得顺手改动灵感数据与页面其他功能。

## 条目 4：「我的」页面新增三块功能

(a) **衣物统计**：衣柜总件数、各品类件数、最常穿单品排行（依据穿搭记录 WearLog 统计；无记录时显示友好的空状态，不要显示 0 排行报错）。
(b) **穿搭统计**：本月记录天数、连续记录天数（按 WearLog 日期本地计算）。
(c) **设置区**：至少包含——温度显示偏好（如 °C/°F）、「灵感默认先看适合今天天气」开关（与条目 2 联动）；设置存本机、重启保留。
要求：全部本地计算，不新增数据上传；统计口径在 PR 说明里写清（例如「最常穿」按记录出现次数计）。

## 条目 5–7：添加衣物照片流水线升级（同一条流水线，分步实现）

现状（wan 真机截图）：添加真人穿着照片时，自动去背景把**整个人**（头、脸、身体、腿）都抠了进来，与现有文案「只保留衣服本身」不符；识别预填的主色被背景带偏（草地/树叶背景把主色判成「绿」），品类漏检（图中有裙装只给了「上装」）。

流水线目标顺序：选照片 →（多人时）选人 → 只提取衣物 → 分开上/下装 → 弄平整 → 高清保存 → 在衣物区域内识别预填。

- **5(a) 多人选人（条目 7）**：照片里检测到多个人物时，先出人物选择界面（框选/点选），用户选定一个再继续；单人照片直接跳过此步。
- **5(b) 只保留衣物（条目 5 主体）**：用本机衣物分割提取衣物区域，不要人像（头、脸、皮肤、腿都不能进结果图）；一件照片里同时有上装和下装时，自动分开：上装、下装各自成图、各自生成一条待确认的新增记录，用户可取消其中之一。
- **5(c) 自动弄平整（条目 5 续）**：把提取出的衣物摆正、拉平，尽量呈现接近平铺图的效果，放在干净背景上。**动手前先在 PR 说明里交实现方案与预期效果**（本机分割+几何摆正能达到什么程度、达不到什么），达不到完全平铺时回落为「分割+裁剪摆正+干净背景」；处理结果要有预览、可退回原图（沿用现有开关交互）。
- **5(d) 识别改进**：主色、品类的识别只在提取出的衣物区域内进行，排除背景干扰；多件衣物时按分开后的每件分别预填；继续保留「自动识别不一定准确，请自行修改」的提示。

## 条目 6：导入照片高清化

现状：照片导入后明显发糊（现导入压缩过狠，抠图输出分辨率也低）。
要求：
- 先定位糊的根源并在 PR 说明里写清（导入压缩参数、抠图/分割的输出分辨率各是多少）。
- 导入改为**保真优先**：提高分辨率与压缩质量上限（给出具体参数与单张体积预估），分割/抠图在高分辨率下执行后再按需缩放。
- 源图本身低清时，提供本机增强（锐化或本机超分方案，仍须 0 成本、本机完成）作为可选处理，结果可对比、可退回。
- PR 附导入前后对比：分辨率、体积、同一区域的清晰度截图。
- 存储变大后的兜底：在「我的」页显示衣物照片占用总量（可并入条目 4 统计区）。

## 条目 8：衣物「换图」入口（手动换商家主图）

背景：wan 有时想用淘宝/抖音的商家主图替换自己拍的照片。已定案**只做手动换图，绝不自动抓取**任何平台图片。
要求：
- 衣物详情/编辑页加「换图」入口：从相册选一张图替换该衣物的照片。
- 替换图不走抠图/平整流水线，保真保存（走条目 6 的高清口径）；替换前有确认，替换后可恢复原图（或保留原图备份直至用户删除该衣物）。
- 不得实现任何形式的平台搜图、抓图、链接解析下载功能。

## 建议的 PR 拆分（可调整，但每个 PR 只做一件事）

1. 条目 3（布局修复，独立小 PR，建议先交）
2. 条目 1 + 2（灵感扩充与天气排序）
3. 条目 4（我的页统计与设置）
4. 条目 5–7（照片流水线；其中 5(c) 先交方案说明再写代码）
5. 条目 6（高清导入；若与 PR4 改动重叠严重可并入 PR4，但说明要分开写）
6. 条目 8（换图入口）

每个 PR：云端编译通过后再交审；说明按「对应条目 / 实现方式 / 成本 / 失败回落 / 自测结果」五段写。
